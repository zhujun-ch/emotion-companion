## 一 答辩先讲清的整体思路

可以这样开场：

“我做的是心屿情绪识别与智能陪伴系统，用户可以在网页和微信小程序里聊天、写日记、查看心情统计，也能匿名发布树洞留言。系统后端使用 Flask，自行训练的 TextCNN 识别六类中文情绪，本机 Ollama 中的大语言模型生成陪伴回复。系统还实现了账号数据隔离、聊天范围控制和树洞人工复核。模型效果通过独立测试集评测，业务流程通过自动化测试验证。”

## 三 TextCNN 情绪识别与训练

### 3.1 输入清洗与文本编码

**关键代码｜emotion_model.py 第 14—23 行**  [打开源码](<F:/workshop/emotion/emotion_model.py:14>)

```python
def normalize_text(text):
    text = unicodedata.normalize('NFKC', text)
    return re.sub(r'\s+', ' ', re.sub(r'https?://\S+', ' ', text)).strip()

def tokenize(text):
    return [x for x in jieba.lcut(normalize_text(text)) if x.strip()]

def encode(tokens, vocab, max_len):
    ids = [vocab.get(t, 1) for t in tokens[:max_len]]
    return ids + [0] * (max_len - len(ids))
```

normalize_text 先做 NFKC 规范化，统一部分全角、半角等字符形式，再移除 URL、合并空白。tokenize 用 jieba 分词。encode 将词转换为整数编号，未知词映射到 1，不足 max_len 时用 0 补齐，过长则截断。训练和推理导入同一套函数，避免两端采用不同分词或标签顺序。

实际最大长度为 96 个分词结果，并非 96 个汉字。PAD 的编号为 0，UNK 的编号为 1；embedding 的 padding_idx=0 对应补齐位置。代码没有额外实现卷积后的 padding 窗口掩码。

### 3.2 模型结构与张量维度

**关键代码｜emotion_model.py 第 25—35 行**  [打开源码](<F:/workshop/emotion/emotion_model.py:25>)

```python
class TextCNN(nn.Module):
    def __init__(self, vocab_size, embed_dim=128, channels=96, kernels=(2,3,4), dropout=.5, num_classes=6, **kwargs):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim, padding_idx=0)
        self.convs = nn.ModuleList([nn.Conv1d(embed_dim, channels, k) for k in kernels])
        self.dropout = nn.Dropout(dropout)
        self.fc = nn.Linear(channels * len(kernels), num_classes)
    def forward(self, x):
        x = self.embedding(x).transpose(1,2)
        features = [F.relu(conv(x)).amax(dim=2) for conv in self.convs]
        return self.fc(self.dropout(torch.cat(features,dim=1)))
```

网络先把词编号转为词向量，再用卷积核长度 2、3、4 分别提取局部词组特征。每条卷积分支输出 96 个通道，ReLU 引入非线性，amax(dim=2) 在序列方向取最大值，保留每个通道最显著的响应。三条分支拼接后得到 288 维向量，经 Dropout 和全连接层输出六个 logits。这里的六类顺序是 angry、fear、happy、neutral、sad、surprise，对应愤怒、恐惧、快乐、中性、悲伤、惊奇。

| 步骤 | 张量形状 | 含义 |
| --- | --- | --- |
| 词编号输入 | [B, 96] | B 为批量大小 |
| Embedding | [B, 96, 128] | 每个词映射到 128 维 |
| transpose | [B, 128, 96] | Conv1d 要求通道在序列长度之前 |
| 三条卷积分支 | [B, 96, 95]、[B, 96, 94]、[B, 96, 93] | 无 padding，输出长度为 96-k+1 |
| 最大池化与拼接 | 每支 [B, 96]，合并 [B, 288] | 提取局部特征并组合 |
| 全连接输出 | [B, 6] | 训练时交叉熵直接接收 logits |

答辩表达：“TextCNN 适合这个项目的短文本分类任务，结构简单，CPU 上也能训练和推理。不同卷积核对应不同长度的局部词组。它对反讽、长距离语义和复杂上下文的表达能力有限，所以系统没有把单句输出直接当成用户真实心理状态。”

词向量由 nn.Embedding 在任务训练中学习。当前实现未加载预训练词向量，未使用 BERT，也未实现注意力网络。

### 3.3 推理如何得到情绪与分数

**关键代码｜emotion_model.py 第 45—53 行**  [打开源码](<F:/workshop/emotion/emotion_model.py:45>)

```python
def probabilities(self, text, temperature=1.0):
    x = torch.tensor([encode(tokenize(text),self.vocab,self.config['max_len'])],dtype=torch.long)
    with torch.inference_mode():
        probs = (self.model(x) / temperature).softmax(dim=1)[0]
    return probs.tolist()
def predict(self, text):
    probs = torch.tensor(self.probabilities(text))
    score, label = probs.max(dim=0)
    return self.config['label_names'][label.item()], score.item()
```

推理用保存的 config.json、vocab.json 和 best_model.pt 恢复模型，model.eval() 关闭训练阶段的 Dropout，torch.inference_mode() 关闭梯度记录。softmax 将六个 logits 转成总和为 1 的分数，argmax 选出得分最高的类别。普通 predict 使用温度 1；多轮参考会使用校准温度。

confidence 是当前模型对文本分类的最大 softmax 分数，不能直接解释为“用户处于某种情绪的真实概率”，也不能解释为心理疾病发生概率。

### 3.4 训练数据怎样处理

**关键代码｜train_textcnn.py 第 28—34 行**  [打开源码](<F:/workshop/emotion/train_textcnn.py:28>)

```python
def clean(rows, excluded=()):
    groups=defaultdict(list)
    for row in rows:
        if row['text']: groups[row['text']].append(row)
    conflicts={text for text,items in groups.items() if len({i['label'] for i in items})>1}
    result=[items[0] for text,items in groups.items() if text not in conflicts and text not in excluded]
    return result, {'raw':len(rows),'retained':len(result),'conflicting_texts':len(conflicts),'excluded_overlap':len(set(groups)&set(excluded))}
```

训练脚本从评测数据集的 train 目录读取 usual 和 virus 两个训练文件，将 eval 目录的已标注文件作为验证集，将“真实评测集”的已标注文件作为最终测试集。文件扩展名虽然是 .txt，脚本实际通过 json.loads 读取内容，不是按 CSV 读取。

clean 按规范化后的文本分组。同一文本标签冲突时整组移除，标签相同的重复文本保留一条；空文本去除。清洗训练集时，还排除与清洗后验证集重叠的文本。词表仅从训练集建立，保留频次不少于 2 的词，并限制候选词数量。

### 3.5 类别不平衡与训练控制

**关键代码｜train_textcnn.py 第 83—87 行**  [打开源码](<F:/workshop/emotion/train_textcnn.py:83>)

```python
frequencies=np.bincount([LABELS.index(r['label']) for r in train],minlength=6)
weights=np.sqrt(frequencies.sum()/frequencies); weights=weights/weights.mean()
criterion=torch.nn.CrossEntropyLoss(weight=torch.tensor(weights,dtype=torch.float32,device=device))
opt=torch.optim.AdamW(model.parameters(),lr=.001,weight_decay=.01)
scheduler=torch.optim.lr_scheduler.ReduceLROnPlateau(opt,mode='max',factor=.5,patience=1)
```

类别数量不均衡，例如清洗后快乐 9011 条、恐惧 1692 条。代码用 sqrt(总数/本类数量) 计算类别权重，并除以平均权重归一化，使少数类在训练损失中获得更高权重。采用平方根后，权重差距比直接使用倒频率温和。

优化器是 AdamW，学习率 0.001，weight_decay 为 0.01。批大小 128，随机种子 42；梯度范数裁剪到 5。学习率调度器观察验证集宏平均 F1，停滞后降低学习率。Dropout=0.5 和 weight decay 用来抑制过拟合。

**最佳模型选择｜train_textcnn.py 第 100—105 行**  [打开源码](<F:/workshop/emotion/train_textcnn.py:100>)


默认最多训练 15 轮，连续 3 轮验证集 macro F1 没有改善就提前停止。每次改善保存 best_model.pt，训练结束加载最佳权重再评测测试集。本项目保存记录为第 8 轮最佳，共训练 11 轮，训练设备为 CPU。

宏平均 F1 先分别计算六个类别的 F1，再取平均，每类权重相同。准确率容易受样本较多的类别影响，macro F1 更能反映少数类别是否被忽略。F1=2PR/(P+R)，其中 P 为精确率，R 为召回率。

## 四 多轮情绪参考为什么不会一上来贴标签

**关键代码｜emotion_reference.py 第 26—37 行**  [打开源码](<F:/workshop/emotion/emotion_reference.py:26>)

```python
def assess(self, previous_user_texts, current_text, turn_count):
    base = {'version':2, 'label':None, 'candidates':[], 'turn_count':turn_count, 'evidence_count':0,
            'state':'collecting', 'reason':'先聊聊，暂不判断情绪'}
    # The first three user messages are a warm-up, not a diagnostic questionnaire.
    if turn_count <= 3:
        return base
    texts = [t for t in previous_user_texts[-4:] + [current_text] if meaningful(t)]
    base['evidence_count'] = len(texts)
    if not meaningful(current_text) or len(texts) < 3:
        return dict(base, state='insufficient', reason='表达信息还不够，先继续聊聊')
    if self.calibration is None:
        return dict(base, state='uncertain', reason='暂不判断，分数校准尚未就绪')
```

前三条 support 或 mixed 用户消息处于收集阶段，暂不输出确定标签。后续取最近最多五条相关用户文本，排除“嗯”“谢谢”等简短附和；当前输入缺少有效表达或有效文本不足三条时，继续提示信息不足。assistant 回复不参与情绪证据，避免模型自己的话影响判断。

需要区分：正常 support 或 mixed 消息仍会进行单句 TextCNN 推理；前三轮不展示确定的多轮参考，不等于前三轮完全不运行情绪模型。

**加权汇总与一致性检查｜emotion_reference.py 第 38—48 行**  [打开源码](<F:/workshop/emotion/emotion_reference.py:38>)

```python
probs = [self.predictor.probabilities(t, self.calibration['temperature']) for t in texts]
# Most recent expressions matter more; no assistant utterances enter this pool.
weights = list(range(1,len(probs)+1))
pooled = [sum(w*p[k] for w,p in zip(weights,probs))/sum(weights) for k in range(len(probs[0]))]
candidate = max(range(len(pooled)), key=pooled.__getitem__)
winners = [max(range(len(p)),key=p.__getitem__) for p in probs]
candidates = [self.predictor.config['label_names'][k] for k in sorted(range(len(pooled)),key=pooled.__getitem__,reverse=True)[:2]]
base['candidates'] = candidates
if winners[-1] != candidate or winners[-3:].count(candidate) < 2:
    return dict(base, state='changing', reason='已分析近期表达，但不同句子的判断不一致，以下仅为初步方向')
threshold = self.calibration['thresholds'][candidate]
```

**阈值检查与结果状态｜emotion_reference.py 第 49—55 行**  [打开源码](<F:/workshop/emotion/emotion_reference.py:49>)

```python
if threshold is None:
    return dict(base, state='uncertain', reason='已完成分析，这类表达的判断把握较低')
strong = sum(w==candidate and p[candidate]>=threshold for w,p in zip(winners[-3:],probs[-3:]))
if probs[-1][candidate] < threshold or strong < 2:
    return dict(base, state='uncertain', reason='已完成分析，判断把握较低，以下仅为初步方向')
return dict(base, state='ready', label=self.predictor.config['label_names'][candidate],
            reason='仅参考近期文字表达，不代表对你的确定判断')
```

多轮策略先用校准温度对每条文本重新计算分数，再以 1、2、3……递增权重汇总，越新的消息权重越大。最高汇总分数对应候选类别。最新一条的获胜类别必须等于候选类别，最近三条至少两条支持该类；最新分数和最近三条中至少两条分数还必须达到对应类别阈值，才输出 ready。否则返回 changing 或 uncertain，并可给出前两个候选方向。

校准文件还保存权重文件的 SHA-256。EmotionReference 初始化时比对当前 best_model.pt 的摘要，匹配才加载校准结果，防止新模型沿用旧阈值。

calibrate_emotion.py 将验证集分为 1915 条温度拟合样本和 1916 条阈值选择样本。温度约为 1.2791；按类别寻找至少覆盖 20 条预测样本且精确率达到 0.8 的阈值。惊奇类别未找到满足条件的阈值，保存为 null，因此不会输出该类别的 ready 确定参考。

0.8 是验证集上的阈值选择目标，不是系统在真实聊天中的准确率保证。验证集也曾用于选模型，多句加权是规则策略；当前没有独立标注的真实多轮会话测试集来证明该策略的会话级准确率。用户反馈保存在 emotion_feedback，当前代码未将反馈自动接入在线训练。

```python
    if not review_reply(user_text, history, route, reply):
        route = 'fallback'
        reply = FIXED_REPLIES[route]
        emotion_label = confidence = emotion_reference = None
```

这是最值得现场展示的一段。classify_message 先判断输入范围。off_topic、clarify、urgent 和 fallback 使用对应固定回复；support 和 mixed 才进入单句识别、多轮参考和回复生成。传给 ask_ollama 的标签是多轮策略输出的 emotion_reference["label"]，而非无条件传递单句预测标签。生成后再检查是否贴合用户处境并留在陪伴范围内，未通过则返回固定 fallback，同时清空该轮情绪结果。

### 6.1 历史怎样保留又避免跑题污染

**关键代码｜conversation_store.py 第 123—140 行**  [打开源码](<F:/workshop/emotion/conversation_store.py:123>)

```python
def context(self, session_id, max_turns=8, char_budget=2400):
    with self.connect() as db:
        rows = db.execute("""SELECT role, COALESCE(model_text, content) AS content
            FROM chat_message WHERE session_id=? AND chat_route NOT IN ('off_topic', 'fallback')
            ORDER BY id DESC LIMIT ?""",
                          (session_id, max_turns * 2)).fetchall()
    history = [dict(r) for r in reversed(rows)]
    selected = []
    for end in range(len(history), 1, -2):
        pair = history[end - 2:end]
        if [m['role'] for m in pair] != ['user', 'assistant']:
            break
        size = sum(len(m['content']) for m in pair)
        if size > char_budget:
            break
        char_budget -= size
        selected = pair + selected
    return selected
```

context 只取当前 session_id 的历史，排除 off_topic 和 fallback。mixed 使用 COALESCE(model_text, content) 优先读取提取后的相关内容。它从最新记录向前选择完整的 user、assistant 消息对，最多 8 轮，并受字符预算限制，防止单条历史过长。app.py 调用时从 2400 字符预算中减去当前输入长度，这个预算只约束历史和当前文本，不包含 system_prompt，也不是 token 数。

澄清和 urgent 消息不在 context 的排除名单中；情绪证据 user_evidence 则只统计 support 和 mixed 的用户消息。因此“大模型对话历史”和“TextCNN 多轮参考证据”有不同筛选口径。

### 6.3 重试为什么不会重复插入

**关键代码｜request_dedup.py 第 37—44 行**  [打开源码](<F:/workshop/emotion/request_dedup.py:37>)

```python
def receipt(db, owner, scope, request_id, content_hash):
    row = db.execute('''SELECT fingerprint, response FROM request_receipt
        WHERE user_id=? AND scope=? AND request_id=?''', (owner, scope, request_id)).fetchone()
    if row is None:
        return None
    if row['fingerprint'] != content_hash:
        abort(409, '该请求编号已用于其他内容，请勿重复使用')
    return json.loads(row['response'])
```

**关键代码｜request_dedup.py 第 47—51 行**  [打开源码](<F:/workshop/emotion/request_dedup.py:47>)

```python
def remember(db, owner, scope, request_id, content_hash, response):
    response = response | {'request_id': request_id}
    db.execute('INSERT INTO request_receipt VALUES (?, ?, ?, ?, ?)',
               (owner, scope, request_id, content_hash, json.dumps(response, ensure_ascii=False)))
    return response
```

request_receipt 的联合主键为 user_id、scope、request_id。fingerprint 对规范化序列化后的业务参数计算 SHA-256；同编号同内容返回原响应，同编号不同内容返回 409。业务记录和回执必须在同一事务里提交，才能避免记录已保存而回执丢失。

## 十一 答辩常见追问及回答要点

### 1 这个项目的核心技术贡献是什么

将短文本情绪分类接入完整陪伴业务，增加多轮参考、输入范围控制和生成后审查；同时完成账号归属、跨端读取、树洞审核及请求去重。这些属于具体算法应用与工程设计，当前没有证据支撑“提出全新神经网络结构”的说法。

### 2 为什么不直接让大模型完成全部情绪判断

独立 TextCNN 有固定六分类标签、可复现的训练过程和测试指标，输出便于做后续统计与校准。大语言模型承担自然语言生成及语义边界判断。两种模型职责清楚，也便于分别分析错误。当前没有做足够的对照实验来证明该组合优于所有纯大模型方案。

### 3 为什么选择 TextCNN 而不是 LSTM 或 BERT

短文本任务可以通过局部词组特征取得可用结果，TextCNN 参数结构较简单、计算成本低，适合本地 CPU 演示。当前没有完成 LSTM、BERT 的同条件对比，因此选择依据是资源和实现条件，不能说实验已证明它最优。

### 4 前三轮为什么看不到确定标签

多轮参考策略主动收集表达，前三条相关消息不输出确定参考。后面还要满足有效文本数量、近期一致性及类别阈值。单句模型仍可能输出分类，但界面参考采用更保守的多轮状态。

### 5 为什么惊奇类别不显示确定结果

在阈值选择数据上没有找到同时满足至少 20 条样本和目标精确率 0.8 的阈值，因此该类阈值设为 null，策略保留候选方向而不输出 ready。

### 6 模型结果与用户感受不一致怎么办

界面提供符合与不符合反馈，并允许更正方向；后台保存反馈及时间。当前反馈用于记录，尚未实现自动重训。回复优先回应用户原话，情绪参考不作为诊断。

### 7 如何避免训练数据泄漏

词表只从训练集建立，训练和验证间去除精确规范化文本重叠；用验证集选模型，最终报告测试结果，并额外给出去重且不与训练验证重叠的测试子集。精确文本去重不能排除语义近似样本，也不能说明所有官方测试样本均无重叠。

### 8 系统记住了所有聊天内容吗

数据库保留完整消息，发给大模型的只是当前会话中经过筛选并受最多 8 轮及字符预算限制的近期历史。数据库保存长度与模型单次上下文长度是两回事。

### 9 同一个消息提交两次会怎样

同账号、同操作、同 request_id 且内容一致时返回旧回执；内容不同返回 409。事务保证只落一份记录。不同 request_id 会被视为不同操作，所以客户端重试必须保留原编号。

### 10 数据库为什么选择 SQLite

当前以单机与局域网演示为目标，SQLite 无需独立数据库服务，易于部署和备份，且能把业务记录与回执放进同一事务。高并发多机部署需整体迁移写入设计，当前 MySQL 模式拒绝启动。

### 11 系统能否脱离互联网运行

已安装依赖、已下载 Ollama 模型且服务在本机时，情绪推理和语言模型调用可以走本地链路。手机仍需能访问电脑后端；初次安装和下载模型需要网络。当前没有提供离线包完整性测试结果。

### 12 为什么聊天响应可能较慢

正常相关请求包含范围分类、回复生成和回复审查，mixed 提取失败时可能再调用一次模型。GPU、模型大小和文本长度都会影响时延。stream=False 意味着前端要等待完整回复。

### 13 是否实现了 RAG 或微调大模型

当前代码没有向量检索知识库和检索增强生成流程，没有大语言模型微调脚本。聊天上下文来自消息表，TextCNN 则有独立监督训练脚本。

### 14 当前还有哪些不足

微博文本与真实倾诉存在领域差异，惊奇和悲伤等类别效果较弱；多轮策略尚缺独立真实会话评测；范围判定和审核仍可能误判。后续优先收集授权标注的领域数据、设计独立会话评测，并开展同条件模型对比。
