## 一、核心文件与服务端口速查

### 1.1 服务与端口映射表

| 服务名称 | 默认监听地址与端口 | 对应启动脚本 | 核心代码入口 |
| --- | --- | --- | --- |
| **本机 Ollama 模型服务** | `127.0.0.1:11434` | `start-ollama.cmd` | `ollama/ollama.exe`（模型目录 `ollama/models`） |
| **Flask 后端服务** | `127.0.0.1:5000` | `start-pages-demo-backend.cmd` / `start-backend.cmd` | `app.py`（生产环境：`serve_production.py`） |
| **用户端网页（Uni-App H5）** | `http://127.0.0.1:5173/` | `start-frontend.cmd` | `frontend/`（依赖 `F:\HBuilderX\plugins\uniapp-cli-vite`） |

### 1.2 核心脚本与文件清单

| 文件路径 | 用途说明 |
| --- | --- |
| `.env` / `.env.example` | 本地环境变量配置（数据库路径、Ollama 地址/模型、审核员口令哈希文件、CORS 与 Host 白名单） |
| `start-ollama.cmd` | 调用 `ollama.cmd serve` 启动本机 Ollama |
| `ollama.cmd` | 固定 `OLLAMA_MODELS=%~dp0ollama\models` 与 `OLLAMA_HOST=127.0.0.1:11434` 后运行 `ollama.exe` |
| `start-backend.cmd` | 激活 `PYTHONUTF8=1` 并用 `.venv\Scripts\python.exe app.py` 启动基础后端 |
| `start-pages-demo-backend.cmd` | 设置 `ENABLE_DEMO_PAGES=1`、`DB_BACKEND=sqlite`，支持传参数 `lan` 监听 `0.0.0.0` |
| `start-frontend.cmd` | 创建 `frontend\node_modules` 联接（若不存在）并启动 H5 开发服务器（5173 端口） |
| `build-demo-miniprogram.cmd` | 编译微信小程序包并自动更新根目录 `project.config.json` 的 `miniprogramRoot`，支持传 `lan` 自动探测局域网 IP |
| `manage_reviewer.py` | 交互式生成审核员密码哈希文件（不覆盖已有文件，密码不回显） |
| `serve_production.py` | 生产环境 Waitress WSGI 启动入口（`APP_ENV=production` 强制校验安全配置） |
| `train_textcnn.py` | 在 `评测数据集/` 上训练六分类 TextCNN 并输出到 `artifacts/emotion_cnn/` |
| `calibrate_emotion.py` | 对训练产物执行验证集温度缩放与类别阈值校准，生成 `calibration.json` |
| `evaluate_chat_boundary.py` | 运行 60 条合成边界用例对比评测，输出到 `artifacts/chat-boundary-evaluation.jsonl` |
| `test_flow.py` / `test-flow.cmd` | 在线冒烟测试（注册随机用户 → 调用 `/api/chat` → 校验 TextCNN/Ollama/SQLite 落库） |
| `inspect_sqlite.py` | 5175 端口只读网页查看本地 SQLite 表结构、索引与行数 |

## 二、首次使用环境准备与配置检查

### 2.1 检查 Python 虚拟环境与依赖
在项目根目录 `F:\workshop\emotion` 下检查 `.venv` 是否可用；若需补充或重装依赖：
```powershell
# 运行依赖（后端服务 + 推理）
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 仅当需要重新训练/校准 TextCNN 时额外安装
.\.venv\Scripts\python.exe -m pip install -r requirements-train.txt
```

### 2.2 检查前端与管理端 Node 依赖
- **独立管理端（`admin/`）**：
  ```powershell
  cd F:\workshop\emotion\admin
  npm.cmd ci
  ```
- **用户端（`frontend/`）**：使用本机 HBuilderX 内置的 `uniapp-cli-vite`（默认路径 `F:\HBuilderX`；如果 HBuilderX 安装在其他位置，启动前需设置环境变量 `HX_APP_ROOT`）。

### 2.3 配置 `.env` 与审核员账户
1. 如果根目录尚未创建 `.env`，先从模板复制：
   ```powershell
   Copy-Item .env.example .env
   ```
2. **生成审核员密码哈希文件**（三端演示模式 `ENABLE_DEMO_PAGES=1` 必需）：
   ```powershell
   .\.venv\Scripts\python.exe manage_reviewer.py artifacts\secrets\reviewer-password.hash
   ```
   按提示输入两次至少 12 位的审核员密码。
3. 编辑 `.env`，确认关键配置：
   ```ini
   DB_BACKEND=sqlite
   SQLITE_PATH=artifacts/demo.sqlite3
   APP_HOST=127.0.0.1
   APP_PORT=5000
   OLLAMA_BASE_URL=http://127.0.0.1:11434
   OLLAMA_MODEL=qwen2.5:7b
   OLLAMA_TIMEOUT=180
   EMOTION_MODEL_DIR=artifacts/emotion_cnn

   DEMO_REVIEWER_USERNAME=admin
   DEMO_REVIEWER_PASSWORD=
   DEMO_REVIEWER_PASSWORD_HASH_FILE=artifacts/secrets/reviewer-password.hash
   DEMO_DATA_DIR=artifacts

   APP_ENV=development
   APP_ALLOWED_ORIGINS=http://127.0.0.1:5173,http://localhost:5173,http://127.0.0.1:5174,http://localhost:5174
   APP_TRUSTED_HOSTS=127.0.0.1,localhost,[::1]
   REVIEWER_ALLOWED_NETWORKS=127.0.0.0/8,::1/128
   ACCOUNT_TOKEN_TTL_SECONDS=2592000
   REQUEST_RECEIPT_TTL_SECONDS=604800
   ```
   > 若只是本地临时调试，也可以把 `DEMO_REVIEWER_PASSWORD_HASH_FILE` 留空并填写 `DEMO_REVIEWER_PASSWORD=你的临时密码`；生产模式（`APP_ENV=production`）严禁使用明文口令。

## 三、方式一：脚本快速启动（日常开发推荐）

分别打开 **4 个终端窗口**，均进入 `F:\workshop\emotion`：

1. **终端 1（Ollama 服务）**：
   ```bat
   start-ollama.cmd
   ```
2. **终端 2（后端三端演示模式）**：
   ```bat
   start-pages-demo-backend.cmd
   ```
   *(若仅测试纯聊天接口不启用树洞/日记演示，可改用 `start-backend.cmd`)*
3. **终端 3（用户端网页 H5）**：
   ```bat
   start-frontend.cmd
   ```
4. **终端 4（独立管理端 Admin）**：
   ```bat
   cd admin
   npx.cmd vite --host 127.0.0.1 --port 5174 --strictPort
   ```

启动后浏览器打开：
- 用户端网页：http://127.0.0.1:5173/
- 独立审核台：http://127.0.0.1:5174/

## 四、方式二：纯手动分步启动（不依赖 `.cmd` 封装脚本）

如果不使用 `.cmd` 脚本，可严格按以下 4 个终端顺序手动执行，便于排查参数和环境变量问题。

### 步骤 1：手动启动本机 Ollama（端口 11434）
在 **终端 1**（PowerShell）：
```powershell
cd F:\workshop\emotion
$env:OLLAMA_MODELS = "F:\workshop\emotion\ollama\models"
$env:OLLAMA_HOST = "127.0.0.1:11434"
.\ollama\ollama.exe serve
```
*(若在 CMD 中：`set "OLLAMA_MODELS=F:\workshop\emotion\ollama\models" && set "OLLAMA_HOST=127.0.0.1:11434" && ollama\ollama.exe serve`)*

验证模型是否存在（另开一个临时终端）：
```powershell
$env:OLLAMA_HOST = "127.0.0.1:11434"
.\ollama\ollama.exe list
# 若未拉取过 qwen2.5:7b，可执行：.\ollama\ollama.exe pull qwen2.5:7b
```

### 步骤 2：手动启动 Flask 后端（端口 5000）
在 **终端 2**（PowerShell）：
```powershell
cd F:\workshop\emotion
$env:PYTHONUTF8 = "1"
$env:DB_BACKEND = "sqlite"
$env:ENABLE_DEMO_PAGES = "1"
$env:APP_HOST = "127.0.0.1"
$env:APP_PORT = "5000"
.\.venv\Scripts\python.exe app.py
```
> 说明：
> - 当 `ENABLE_DEMO_PAGES=1` 时，聊天数据库为 `artifacts\pages_chat_demo.sqlite3`，树洞/日记数据库为 `artifacts\pages_demo.sqlite3`。
> - 当 `ENABLE_DEMO_PAGES` 未设置或为 `0` 时，只挂载账号与聊天接口，数据库为 `.env` 中的 `SQLITE_PATH`（默认 `artifacts\demo.sqlite3`）。

验证后端就绪：
```powershell
Invoke-RestMethod http://127.0.0.1:5000/api/ping
```
看到返回 `"status": "success"` 及六类情绪标签即表示模型加载与接口正常。

### 步骤 3：手动启动用户端网页 H5（端口 5173）
在 **终端 3**（PowerShell）：
```powershell
cd F:\workshop\emotion\frontend

# 首次运行若 frontend\node_modules 不存在，先建立目录联接指向 HBuilderX 的依赖
if (-not (Test-Path node_modules)) {
  cmd /c mklink /J node_modules "F:\HBuilderX\plugins\uniapp-cli-vite\node_modules"
}

$env:HX_APP_ROOT = "F:\HBuilderX"
$env:UNI_INPUT_DIR = "F:\workshop\emotion\frontend"
$env:UNI_OUTPUT_DIR = "F:\workshop\emotion\frontend\unpackage\dist\dev\h5"
$env:UNI_CLI_CONTEXT = "$env:HX_APP_ROOT\plugins\uniapp-cli-vite"
$env:UNI_PLATFORM = "h5"

# 如果后端不在本机 5000 端口，可显式指定：$env:VITE_API_BASE = "http://127.0.0.1:5000"
node "$env:UNI_CLI_CONTEXT\node_modules\@dcloudio\vite-plugin-uni\bin\uni.js" --config "$env:UNI_CLI_CONTEXT\vite.config.js" --host 127.0.0.1 --port 5173 --strictPort
```

### 步骤 4：手动启动独立管理端 Admin（端口 5174）
在 **终端 4**（PowerShell）：
```powershell
cd F:\workshop\emotion\admin
# 首次运行如未安装依赖：npm.cmd ci
npx.cmd vite --host 127.0.0.1 --port 5174 --strictPort
```
若需打包生成生产静态文件（输出至 `admin\dist\`，使用 `./` 相对路径适配 Nginx `/admin/` 子路径）：
```powershell
cd F:\workshop\emotion\admin
npx.cmd vite build
```

## 五、微信小程序构建与真机局域网联调

### 5.1 本机微信开发者工具预览构建
脚本一键方式：
```bat
build-demo-miniprogram.cmd
```
或纯手动 PowerShell 方式：
```powershell
cd F:\workshop\emotion\frontend
$env:HX_APP_ROOT = "F:\HBuilderX"
$env:UNI_INPUT_DIR = "F:\workshop\emotion\frontend"
$env:UNI_CLI_CONTEXT = "$env:HX_APP_ROOT\plugins\uniapp-cli-vite"

node "$env:UNI_CLI_CONTEXT\node_modules\@dcloudio\vite-plugin-uni\bin\uni.js" build -p mp-weixin --config "$env:UNI_CLI_CONTEXT\vite.config.js"
```
构建完成后，更新根目录 `project.config.json` 中的 `"miniprogramRoot"` 为 `"frontend/unpackage/dist/dev/<目录名>/"`，并在 **微信开发者工具** 点击 **「项目 → 重新打开此项目」** 后编译。

### 5.2 手机同局域网真机调试步骤
1. 查看电脑当前局域网 IPv4（例如 `192.168.1.25`）。
2. 修改 `.env` 中的 `APP_TRUSTED_HOSTS`，把电脑局域网 IP 加进去（如 `APP_TRUSTED_HOSTS=127.0.0.1,localhost,[::1],192.168.1.25`）；若还有手机浏览器直接访问 H5，也把 `http://192.168.1.25:5173` 加入 `APP_ALLOWED_ORIGINS`。
3. 后端以局域网监听模式启动（`APP_HOST=0.0.0.0`）：
   ```bat
   start-pages-demo-backend.cmd lan
   ```
4. 构建绑定局域网后端地址的小程序包：
   ```bat
   build-demo-miniprogram.cmd lan
   ```
   *(若电脑有多块网卡导致脚本无法自动确定唯一 IP，可先手动设置 `set VITE_API_BASE=http://192.168.1.25:5000` 再运行 `build-demo-miniprogram.cmd`)*
5. 在微信开发者工具重新打开根目录项目并点击「真机调试」扫码。

## 六、生产环境部署启动与常用工具命令

### 6.1 生产环境 WSGI 启动（Waitress + Nginx 反代）
`app.py` 禁止直接以 `APP_ENV=production` 运行，必须通过 `serve_production.py` 启动，并在前置 Nginx 配置 HTTPS 与 `/api/demo/review/`、`/admin/` 的来源 IP 限制（参考 `deploy\nginx.conf.example`）：
```powershell
cd F:\workshop\emotion
$env:APP_ENV = "production"
$env:ENABLE_DEMO_PAGES = "1"
$env:DB_BACKEND = "sqlite"
$env:APP_ALLOWED_ORIGINS = "https://emotion.example.com"
$env:APP_TRUSTED_HOSTS = "emotion.example.com"
$env:REVIEWER_ALLOWED_NETWORKS = "127.0.0.1/32"
$env:DEMO_REVIEWER_PASSWORD = ""
$env:DEMO_REVIEWER_PASSWORD_HASH_FILE = "artifacts/secrets/reviewer-password.hash"
.\.venv\Scripts\python.exe serve_production.py
```

### 6.2 模型训练、校准与评测
```powershell
# 1. 训练 TextCNN（产物写入 artifacts/emotion_cnn/）
.\.venv\Scripts\python.exe train_textcnn.py --epochs 15 --patience 3

# 2. 拟合温度缩放并生成类别阈值（calibration.json）
.\.venv\Scripts\python.exe calibrate_emotion.py --output artifacts/emotion_cnn

# 3. 对话边界三配置对比评测（需提前启动 Ollama）
.\.venv\Scripts\python.exe evaluate_chat_boundary.py
```

### 6.3 自动化测试与数据库运维
```powershell
# 运行全部后端单元测试（48 项）
.\.venv\Scripts\python.exe -m unittest discover -s tests -v

# 运行前端请求编号重试单测
node --test frontend/composables/requestIds.test.mjs

# 运行在线冒烟测试（需先启动 Ollama 和后端）
.\.venv\Scripts\python.exe test_flow.py

# 启动 SQLite 只读结构与行数查看器（http://127.0.0.1:5175/）
.\.venv\Scripts\python.exe inspect_sqlite.py

# 一致性在线备份 SQLite（使用 SQLite backup API，安全不锁损坏）
.\.venv\Scripts\python.exe -c "import sqlite3; src=sqlite3.connect('artifacts/pages_chat_demo.sqlite3'); dst=sqlite3.connect('artifacts/backup_chat.sqlite3'); src.backup(dst); dst.close(); src.close()"
```

## 七、常见启动与运行故障排查

| 现象 / 报错 | 常见原因 | 排查与解决方法 |
| --- | --- | --- |
| 启动提示 `请配置审核员密码哈希或本地演示口令` | `.env` 未配置 `DEMO_REVIEWER_PASSWORD_HASH_FILE` / `DEMO_REVIEWER_PASSWORD` | 运行 `manage_reviewer.py` 生成哈希文件并在 `.env` 中配置路径 |
| 接口返回 `400` 且提示 Host 不可信，或 `403 当前网页来源不允许访问` | 局域网访问时未将 IP/来源加入白名单 | 在 `.env` 的 `APP_TRUSTED_HOSTS` 加入访问主机/IP，在 `APP_ALLOWED_ORIGINS` 加入完整来源（协议+主机+端口）并重启后端 |
| 树洞管理员登录/审核报 `403 当前网络不允许访问审核接口` | 非本机回环地址请求审核接口 | 本机使用 `127.0.0.1` 打开页面；远程审核须在 `REVIEWER_ALLOWED_NETWORKS` 配置管理 VPN 网段 |
| 聊天或树洞提交返回 `502` / 一直转人工审核 | Ollama 未启动、端口不对或未拉取 `qwen2.5:7b` | 检查 `11434` 端口监听状态及 `ollama.exe list` 输出 |
| 登录/注册返回 `429 尝试次数过多` | 15 分钟内同一账号（或开发模式同 IP）请求超过 10/40 次 | 等待 15 分钟或检查客户端是否死循环重试 |
| `start-frontend.cmd` 报找不到 `uni.js` | 本机 HBuilderX 不在 `F:\HBuilderX` | 启动前执行 `set "HX_APP_ROOT=你的HBuilderX路径"` 并删掉旧 `frontend\node_modules` 联接后重试 |
| 端口被占用（5000 / 5173 / 5174 / 11434） | 上次残留进程未关闭 | 用 `Get-NetTCPConnection -LocalPort 5000,5173,5174,11434 -State Listen` 查出 `OwningProcess` PID 后 `Stop-Process -Id <PID>` 结束 |
